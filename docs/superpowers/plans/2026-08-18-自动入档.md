# 自动入档 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** 在不启用 AI 的前提下，保存包含文字的新记录时按用户选择的分类自动生成一条已确认档案，同时保留旧记录的手动补录入口。

**Architecture:** 复用现有 MemoryService.createManualClaim 和本地 MemoryClaim 构造逻辑。记录创建函数改为返回 MemoryEntry，保存成功后顺序执行自动入档；原始记录失败不清空表单，自动入档失败保留原始记录并给出手动补录提示。离线草稿增加可选分类字段，旧草稿缺失分类时只提交原始记录。

**Tech Stack:** React 19、TypeScript、Vitest、Testing Library、fake-indexeddb、现有 CSS 与 Supabase 服务层。

## Global Constraints

- 文字记录保存前必须选择分类；提示固定为“请选择档案分类”。
- 图片或语音且无文字时可以不选分类并直接保存。
- 自动档案内容等于整条原始文字，固定为 explicit + confirmed + active。
- 旧记录继续保留“加入档案”手动补录入口。
- 正式账号先调用 createEntry，再调用 createManualClaim；不调用任何 AI 接口。
- 自动入档失败不删除已经保存的原始记录。
- demo=1 和本地模式不调用云端、不持久化到服务端。
- 不增加数据库表、Edge Function、依赖或批量入档。
