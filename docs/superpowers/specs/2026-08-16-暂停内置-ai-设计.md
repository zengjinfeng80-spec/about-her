# “雪梨”暂停内置 AI 设计

## 目标

暂时关闭“雪梨”的全部内置 AI 入口和后台调用。用户仍可使用邮箱登录，在不同设备保存和同步文字、图片及录音记录；后续确有需要时，再单独开发并配置 AI。

## 用户界面

- 隐藏底部导航中的“问记录”，其余“档案、记录、回忆”保持不变。
- 隐藏记录卡片中的分析状态、分析错误和“重试”按钮。
- 不显示“AI 暂未启用”等占位提示，避免把暂不提供的能力保留为可见入口。
- 登录、设置、档案、待确认、记录、回忆、搜索、导出和删除界面保持不变。

## 保存流程

新建记录时继续保存原始文字、发生时间和附件，并保持现有云端同步流程。记录的 `analysis_status` 写为 `idle`，但客户端不再创建 `analysis_jobs`，也不再调用 `analyze-entry`。

图片和录音只作为原始附件保存，不进行图片理解、语音转写或内容提取。保存成功与否只取决于记录和附件是否成功写入，不受 AI 服务状态影响。

## 保留边界

- 保留现有数据库表、分析字段、Edge Functions 和 AI 相关服务端代码，避免为暂停功能执行破坏性迁移。
- 现有记录的分析状态和历史分析任务不删除，只是不再在界面展示或由客户端继续触发。
- Gemini 实现继续保留在 `codex/gemini-free-tier` 隔离分支，不合并、不推送、不部署。
- 不创建、保存或部署 Gemini API Key，也不配置其他模型供应商。

## 错误处理

- 记录或附件保存失败时，继续使用现有保存错误提示。
- 因为客户端不再调用 AI，所以新记录不得出现由分析请求造成的“分析失败”或保存失败。
- 历史记录即使带有 `queued`、`processing` 或 `failed` 状态，也不影响查看、导出或删除。

## 验证标准

1. 保存纯文字、图片和录音记录时，记录与附件均可正常同步。
2. 新记录的 `analysis_status` 为 `idle`，且没有新增 `analysis_jobs`。
3. 保存记录时没有对 `analyze-entry` 或 `ask-memory` 的网络请求。
4. 页面不显示“问记录”、分析状态、分析错误或分析重试入口。
5. 登录、跨设备同步、档案、待确认、回忆、搜索、导出和删除行为不回归。
6. 自动化测试、类型检查和生产构建通过，并在桌面及手机视口完成浏览器检查。

## 后续恢复

未来重新启用 AI 时，另行确认模型供应商、免费额度、隐私边界和用户界面，再通过新的设计与实施计划恢复分析任务和“问记录”。本次暂停不预先承诺具体模型或恢复日期。
