# 邮箱验证码登录设计

## 目标

将现有的邮箱链接登录改为 6 位邮箱验证码登录。用户始终留在“关于她”页面，不再依赖邮件链接回跳，从而避免 GitHub Pages 子路径 404。

## 方案选择

- **同页两步式（采用）**：先输入邮箱并发送验证码，再切换为验证码输入。步骤清楚，手机上不同时堆叠两组表单。
- 同屏显示邮箱和验证码：代码稍少，但用户可能在尚未发送时就尝试输入验证码。
- 保留邮件链接：交互步骤少，但仍受回调路径、链接过期和邮件客户端打开方式影响，不再采用。

## 交互与数据流

1. 用户输入邮箱，点击“发送验证码”。
2. 前端调用 `signInWithOtp({ email })`；Supabase 邮件模板只发送 `{{ .Token }}`，不发送登录链接。
3. 页面显示 6 位验证码输入框、当前邮箱、“验证并登录”、“重新发送”和“修改邮箱”。
4. 用户提交后，前端调用 `verifyOtp({ email, token, type: 'email' })`。验证成功后沿用现有会话监听逻辑进入档案。
5. 验证码固定为 6 位数字，有效期 10 分钟，重新发送仍遵守 Supabase 的 60 秒发送频率限制。

## 错误处理

- 发送失败时保留邮箱，显示服务端错误或统一失败提示。
- 验证码不正确或过期时保留验证码页面，提示重新检查或发送。
- “修改邮箱”返回第一步并清空验证码。
- 连续点击期间禁用当前操作按钮，避免重复请求。

## 验收标准

- 测试覆盖发送验证码、进入第二步、验证成功调用、修改邮箱和错误提示。
- Supabase 远端配置为 6 位验证码、10 分钟有效期，邮件正文包含验证码。
- 生产构建和 GitHub Pages 部署通过；线上登录页不再显示“发送登录链接”。
- 使用真实新邮件完成一次“发送验证码 → 输入验证码 → 进入私人档案”验收。

## 边界

不新增密码登录、第三方登录、手机号登录或密码找回。数据权限、会话持久化和登出逻辑保持不变。
